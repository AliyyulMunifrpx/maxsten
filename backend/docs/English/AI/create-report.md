# AI Store Report

Generates a summary of store performance for a specific month, written in natural language by AI, complete with practical recommendations.

## Endpoint

```
POST /api/ai/reports

```

> ⚠️ **The response can take up to ~30 seconds** — this endpoint calls a third-party AI service, making it much slower than other endpoints. The frontend is required to display a clear loading state (not a standard instant spinner), and ideally provide a "generating report..." indicator to the user.

## Auth

Cookie-based auth. `userId` from `req.user` (middleware).

## Request

Content-Type: `application/json`

| Field   | Type   | Required | Description                                                       |
| ------- | ------ | -------- | ----------------------------------------------------------------- |
| `month` | number | ❌       | `1`–`12`. Defaults to the current month (in the store's timezone) |
| `year`  | number | ❌       | Defaults to the current year (in the store's timezone)            |

## Example Request

```bash
curl -X POST https://example.com/api/ai/reports \
  -b "access_token=<token>; refresh_token=<token>" \
  -H "Content-Type: application/json" \
  -d '{"month": 7, "year": 2026}'

```

## Response

### 200 OK

```json
{
  "data": {
    "ai_report": {
      "greeting": "Halo Kak Budi,",
      "evaluation": "Performa toko kamu bulan ini cukup solid dengan omzet Rp3.500.000 dari 108 pesanan berhasil. Tingkat pembatalan masih terkendali di 5.3%, dan rata-rata waktu tunggu pelanggan terbilang cepat...",
      "recommendations": [
        "Pertimbangkan menambah stok Nasi Goreng Spesial karena jadi produk terlaris bulan ini.",
        "Jam 12:00-13:00 adalah waktu tersibuk — pastikan staf cukup di jam tersebut untuk menjaga waktu tunggu tetap singkat."
      ]
    }
  }
}
```

**Scenario with no transactions at all in the requested month** — the response maintains the same structure, but the content uses a static template (not generated by AI, so the AI request is never sent in this case, making it faster and avoiding API costs):

```json
{
  "data": {
    "ai_report": {
      "greeting": "Halo Kak Budi,",
      "evaluation": "Belum ada data transaksi yang bisa dievaluasi pada periode ini.",
      "recommendations": [
        "Coba bagikan link tokomu ke media sosial untuk menarik pelanggan pertama bulan ini!"
      ]
    }
  }
}
```

### Error

| Status | Condition                                                                                                              | `errors`                                                |
| ------ | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 400    | `month`/`year` are invalid (`month` outside `1`–`12`, or not a number)                                                 | `Invalid month/year parameters`                         |
| 401    | Not logged in / session expired                                                                                        | `Unauthorized`                                          |
| 404    | User does not have a store yet                                                                                         | `Store not found`                                       |
| 500    | Failed to get a response from AI (~30 second timeout, AI service down, or response does not match the expected format) | `Unable to obtain an analysis from the AI at this time` |

## Notes

- The data used to generate the report (revenue, order count, cancellation rate, average wait time, busiest hours/days, top 3 products & top 3 add-ons) is exactly the same as what is calculated in `GET /api/stores/me/history` — this AI report essentially "translates" those numbers into a narrative rather than being a new data source.
- `recommendations` is always an array of strings — the number of items may vary depending on the AI's output, not guaranteed to always be 2 as shown in the example.
- If the AI fails to respond in the expected format (e.g., invalid JSON or missing fields), the entire request fails with a `500` status — there are no partial responses.
